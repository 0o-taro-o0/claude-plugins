# 作業報告

指揮役がオーナーへ報告するときに使う。1行目に結論を書く。

```markdown
結論: <オーナーが次に何をすればよいか。1行>

## 行ったこと

<1〜3行>

## 成果物

- PR #<番号> <題名> — マージ可
- Issue #<番号> を起票

## 検証した内容

<実行したコマンドと、その結果>

## レビューの指摘と対応

- 差し戻し <件数> → 対応済み
- 推奨 <件数> → <件数> 件は対応済み、<件数> 件は別の PR #<番号> で対応、<件数> 件は Issue #<番号> へ起票

## 判断を仰ぎたいこと

なし
```

## 注意事項

- 結論には、読んだオーナーが次に何をすればよいかを1行で書く。
  `完了(判断待ちなし)` `PR #<番号> のマージ待ち` `判断待ち <件数>` のように示す。
  作業の途中で報告する場合は `進行中(<対象>、完了見込み <日時>)`
  のように、対象と見込みを添える。埋められない欄は「該当なし」と書く。
- 成果物には、プルリクエスト、起票した GitHub Issue の番号、作成した記録など、
  リポジトリに残ったものを列挙する。何も残らない作業であれば「なし」と書く。
- 判断を要する件が1件でもあれば、`/workflow:decision-request` の書式で判断依頼
  Issue を起票し、「判断を仰ぎたいこと」にその番号と題名を列挙する。
  判断を求める文章を報告やプルリクエストに直接書かない。複数あれば重い順に並べる。
- 参照先を開かなくても意味が通るように書く。数値やエラーの実物は本文に書き写す。
- `CLAUDE.md`「判断を仰ぐこと」に該当しないものは書かない。自分で決めて進める。気づいた課題は
  `CLAUDE.md`「進め方」に従う。
