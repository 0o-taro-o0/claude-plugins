# 判断依頼

オーナーへ判断を求めるときに使う。

    該当: <CLAUDE.md「判断を仰ぐこと」のどれに当たるか>

    何が起きているか:
      <前提知識なしで読める説明。3〜5行。
       関連する数値、ファイル名、エラーの実物は、参照ではなくここに書き写す>

    なぜ判断が必要か:
      <こちらで決められない理由。1〜2行>

    選択肢:
      A. <案> → <選んだ場合に何が起きるか。所要時間や費用も書く>
      B. <案> → <同上>

    推奨:
      <どれを推すか。理由を1〜2行>

    放置した場合:
      <期限があるかどうか。なければ「特に問題は生じない」と書く>

    判断結果の記録先:
      <判断が出たら、どこへ反映するか。基準文書、決定の記録、プルリクエストなど>

## 起票

書式を埋めたら、GitHub Issue として起票する。起票した Issue を正とし、判断の結果も
Issue に残す。Web から起票する場合は Issue テンプレート「判断依頼」を使う。
コマンドから起票する場合は、書式を埋めた本文をそのまま渡す(テンプレートは適用されない)。

    gh issue create --title "判断依頼: <題名>" --body-file <書式を埋めたファイル>

判断依頼は1件につき1つの Issue とする。判断が出たら、判断結果の記録先へ反映してから
Issue をクローズし、クローズコメントに判断の内容と反映先を書く。

## 注意事項

- 作業報告のなかで判断を求める場合は、別のメッセージやファイルへ切り出さず、
  作業報告の「判断を仰ぎたいこと」に上の項目をそのまま書き、起票した Issue の番号を添える。
- 参照先を開かなくても意味が通るように書く。
- 軽重を混ぜない。重い判断と軽い判断を同じ一覧に並べない。
- 「判断を仰ぐこと」に該当しないものは、自分で決めるか GitHub Issue へ回す。
