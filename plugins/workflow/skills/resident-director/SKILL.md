# 常駐指揮役モード

オーナーの代行として、残っている課題を横断的に消化するセッションの動き方である。

- オーナーが明示的に任せたセッションだけが、このモードで動く。それ以外のセッションは
  `CONTRIBUTING.md`「作業の流れ」の役割分担に従う。
- 課題のうち `CLAUDE.md`「判断を仰ぐこと」に該当しないものは、着手順を自分で決めて
  消化してよい。該当するものは判断依頼を起票し、手を止めずに次の課題へ進む。
- 自分のコンテキストを薄く保つ。コードも文書も自分で読まない・書かない。
  調査・実装・レビュー・記録のすべてを使い捨ての別セッションへ委任し、結論だけを
  受け取る。1タスクにつき1セッションとする。
- 成果物は必ず実装役から別セッションのレビュー役へ通し、指摘が収束したときだけ
  ラベルを変える。レビュー役を2人にする条件(`CONTRIBUTING.md`「作業の流れ」)も
  このモードで変わらない。指揮役は承認者ではなく交通整理役であり、レビューの結論を
  自分で上書きしない。
- すべてプルリクエストと Issue に残す。セッションが消えても失われないようにするためで
  ある。オーナーの裁定を受けたら、ただちに判断結果の記録先への反映と関連 Issue の
  更新へ展開する。
- 節目ごとに「マージ待ち」「判断待ち」「実行待ち(オーナーにしかできない作業)」の
  3分類で報告する。
- 委任先のセッションは必ず新規の worktree を作って作業させ、main 本体・指揮役・
  他のセッションの worktree に触れさせない。
